# VitalSense Pressure Risk ML Model

> **Status:** Engineering prototype / synthetic teacher model  
> **Target deployment:** Silicon Labs EFR32xG26  
> **Model family:** Small MLP for embedded pressure-risk inference  
> **Last README revision:** 2026-08-13

This folder contains the VitalSense `pressure_risk_mlp` model and deployment artifacts.

The model is designed to estimate a **normalized engineering pressure-risk score** for four body regions:

- Head
- Shoulders
- Hips
- Heels

The current model is trained primarily on **synthetic labels generated by an engineering teacher function**. It is **not a clinically validated pressure-ulcer probability model**.

# 3. Model Inputs

The neural network receives **12 features in a fixed order**.

| Index | Feature | Description | Expected Range |
|---|---|---|---|
| 0 | `position_CENTER` | CENTER posture one-hot | {0, 1} |
| 1 | `position_LEFT` | LEFT posture one-hot | {0, 1} |
| 2 | `position_RIGHT` | RIGHT posture one-hot | {0, 1} |
| 3 | `log_duration_normalized` | Log-scaled same-position duration | approximately [0, 1] for 0–7200 s |
| 4 | `head_load` | Normalized head pressure | [0, 1] |
| 5 | `shoulders_load` | Normalized shoulder pressure | [0, 1] |
| 6 | `hips_load` | Normalized hip pressure | [0, 1] |
| 7 | `heels_load` | Normalized heel pressure | [0, 1] |
| 8 | `head_exposure_scaled` | Head pressure-duration exposure feature | [0, 1] |
| 9 | `shoulders_exposure_scaled` | Shoulder pressure-duration exposure feature | [0, 1] |
| 10 | `hips_exposure_scaled` | Hip pressure-duration exposure feature | [0, 1] |
| 11 | `heels_exposure_scaled` | Heel pressure-duration exposure feature | [0, 1] |

## Duration preprocessing

The documented duration feature is:

```python
log_duration_normalized = (
    np.log1p(duration_sec)
    / np.log1p(7200.0)
)
```

If durations greater than 7200 seconds are accepted by production firmware, the intended clipping or extrapolation behavior must be explicitly defined and kept identical between training and firmware.

# 4. Firmware-Facing Inputs

The firmware wrapper does **not** require the caller to provide all 12 neural-network features.

The application-facing wrapper accepts **six logical inputs**:

1. `position`
2. `duration_sec`
3. `head_adc`
4. `shoulders_adc`
5. `hips_adc`
6. `heels_adc`

The wrapper is responsible for generating the 12 model features before inference.

Example API:

```c
sl_status_t pressure_risk_ml_predict(
    pressure_position_t position,
    uint32_t duration_sec,
    uint16_t head_adc,
    uint16_t shoulders_adc,
    uint16_t hips_adc,
    uint16_t heels_adc,
    pressure_risk_result_t *result
);
```

> Previous documentation incorrectly referred to this as a five-input API. It is six logical inputs plus the output/result pointer.

# 6. Synthetic Teacher Model

The current labels are generated from a physics-inspired / engineering risk function.

The documented teacher relationship is:

```python
risk_zone = (
    risk_gain
    * (pressure ** pressure_exponent)
    * np.log1p(duration_sec / reference_duration_seconds)
)

risk_zone = max(risk_zone, relief_floor)
```

Current parameters:

| Parameter | Value |
|---|---:|
| `reference_duration_seconds` | 7200 |
| `relief_floor` | 0.1 |
| `pressure_exponent` | 1.5 |
| `risk_gain` | 1.5 |
| `low_medium_threshold` | 35.0 |
| `medium_high_threshold` | 70.0 |

## Critical target-range requirement

The neural-network output uses a sigmoid and is therefore restricted to:

```text
0 ≤ model_output ≤ 1
```

However, the documented teacher equation can exceed `1.0`.

For example:

```text
pressure = 1.0
duration = 7200 sec

1.5 × 1.0^1.5 × log(2)
≈ 1.0397
```

Therefore, the **training target must have a clearly defined range**.

For future retraining, use an explicit clamp such as:

```python
risk_zone = (
    risk_gain
    * (pressure ** pressure_exponent)
    * np.log1p(duration_sec / reference_duration_seconds)
)

risk_zone = max(risk_zone, relief_floor)
risk_zone = np.clip(risk_zone, 0.0, 1.0)
```

> **Verification required for the existing trained model:** Check the actual training script to confirm whether clipping to `[0,1]` was already applied. The previous README did not document this. Do not assume the current `.pt` model was trained with clipping until the training code is verified.

# 7. Risk Levels

Risk level thresholds are applied to the **0–100 engineering risk score**.

```text
LOW     : score < 35
MEDIUM  : 35 ≤ score < 70
HIGH    : score ≥ 70
```

Current thresholds:

| Transition | Threshold |
|---|---:|
| LOW → MEDIUM | 35 |

These are **engineering thresholds**, not clinical diagnostic thresholds.

# 9. ADC → Load Calibration

Current regional ADC normalization:

| Region | q05 | q95 |
|---|---:|---:|
| Head | 3119 | 3932 |
| Shoulders | 3537 | 3994 |
| Hips | 3007 | 3909 |
| Heels | 3222 | 4021 |

Current normalization:

```python
load = np.clip(
    (adc - q05) / (q95 - q05),
    0.0,
    1.0
)
```

## Calibration warning

These q05/q95 constants are a major part of the inference pipeline.

If they were derived from a limited number of people, sessions, mattresses, or physical sensor mats, they may not generalize to new subjects or hardware.

A future population study should compare:

```text
A. global per-region normalization
B. baseline-corrected normalization
C. sensor-mat-specific normalization
D. population percentile normalization
E. learned normalization
F. combinations of the above
```

Do not calculate future q05/q95 calibration statistics from the full dataset before the train/validation/test split.

Correct process:

```text
split by subject
      ↓
fit calibration / normalization using TRAIN subjects only
      ↓
freeze calibration
      ↓
apply exactly the same calibration to VALIDATION and TEST
```

The currently reported model used:


# 13. Current Performance

Current documented test set:

```text
12,000 rows
24 synthetic subjects
```

Current metrics:

| Metric | Value |
|---|---:|
| MAE, risk points 0–100 | 1.88 |
| RMSE, risk points 0–100 | 2.75 |
| Maximum absolute error | 21.19 |
| Highest-risk body-part accuracy | 90.2% |
| Highest-risk level accuracy | 97.0% |

## Interpretation

The average error is low for imitation of the synthetic engineering teacher.

However, the following require additional analysis:

### Maximum error

A maximum absolute error of `21.19` risk points is materially larger than the average error.

The error report should identify:

- body region
- posture
- duration
- normalized load
- risk level
- subject
- proximity to clipping
- proximity to the 35/70 thresholds

### Highest-risk body-part accuracy

A body-part accuracy of `90.2%` should be interpreted together with the score margin between the highest and second-highest regions.

Example:

```text
Teacher:
Head = 54
Hips = 53

Model:
Head = 52
Hips = 53
```

The body-part classification changes even though the numerical error is small.

For future reports calculate:

```python
risk_margin = highest_risk_score - second_highest_risk_score
```

and report highest-risk-body-part accuracy by margin band:

```text
< 2 points
2–5 points
5–10 points
> 10 points
```

# 17. Model Purpose: Student of an Engineering Teacher

The current neural network is primarily learning to approximate a deterministic engineering teacher that itself depends on pressure and duration.

Conceptually:

```text
ADC
  ↓
normalized load
  ↓
pressure + duration
  ↓
engineering teacher
  ↓
target risk score
  ↓
small MLP student model
```

This is valid for:

- embedded prototype integration
- replacing a more complex computation with a compact model
- validating the deployment toolchain
- preparing for later population-trained models

It does **not** independently establish clinical predictive validity.

For the present synthetic stage, benchmark both:

```text
A. direct teacher-function implementation
B. MLP approximation
```

on the target MCU for:

- flash
- RAM
- latency
- power
- numerical error
- implementation complexity

The MLP becomes more valuable as the model evolves beyond a fixed teacher equation and learns from diverse real-subject data.

# 19. ONNX → TFLite for Silicon Labs

Do **not** use `tf2onnx` for ONNX → TFLite conversion.

`tf2onnx` is a TensorFlow/TFLite → ONNX converter and is the wrong conversion direction for this deployment path.

For current Silicon Labs tooling, use **Simplicity Machine Learning**.

Check version:

```bash
sml --version
```

The converter is available in Simplicity Machine Learning CLI versions that provide:

```bash
sml convert
```

Convert the ONNX model:

```bash
sml convert \
    pressure_risk_mlp.onnx \
    --output pressure_risk_mlp.tflite \
    --save-manifest \
    --log-level info
```

For help:

```bash
sml convert --help
```

## Current converter behavior

The Silicon Labs converter currently produces a **float32 TFLite model**.

Do not assume that conversion applies:

- INT8 quantization
- FP16 quantization

unless a later verified toolchain explicitly does so.

Always validate the generated `.tflite` model against the ONNX/PyTorch model using representative inputs.

# 26. Highest-Risk Body Part

The highest-risk region should be derived from:

```python
regional_scores = {
    "head": head_risk_score,
    "shoulders": shoulders_risk_score,
    "hips": hips_risk_score,
    "heels": heels_risk_score,
}

highest_risk_body_part = max(
    regional_scores,
    key=regional_scores.get
)
```

For testing, explicitly handle exact or near ties.

A change in highest-risk body part is less significant when the two leading regional scores are nearly equal.

Store or calculate:

```python
highest_score
second_highest_score
risk_margin = highest_score - second_highest_score
```
